# CMS Debate Kit

발췌문에서 확인되는 내용만 사용하여 수업용 토론 키트를 만들고 인용의 정확성을 끝까지 추적한다.

## 시작 전 확인

1. 작업 루트, 발췌문 파일, 기존 토론 규칙·양식·검증기, `결과물` 폴더를 읽기만 하여 확인한다.
2. 활동지와 루브릭을 만들 때는 대상 학년·수준과 적용 성취기준을 먼저 확인한다. 자료에 없고 사용자도 제시하지 않았다면 추정하지 말고 `확인 필요`로 표시한다.
3. 파일을 만들거나 수정하기 전에 작업 내용, 대상 파일, 예상 결과, 저장 예정 절대 경로를 먼저 제시하고 사용자의 명시적 승인을 기다린다.
4. 승인된 파일과 범위만 처리한다. 추가 산출물이 필요하면 다시 승인받는다.

## 절대 규칙

- 발췌문에 없는 사실, 작품 배경, 줄거리, 작가 정보, 일반 지식을 토론 근거로 쓰지 않는다.
- 주장에 필요한 근거를 발췌문에서 찾을 수 없거나 인과관계·의도·결과가 직접 확인되지 않으면 지어내지 말고 정확히 **`발췌문에서 확인 불가`**라고 표시한다.
- 직접 인용은 발췌문의 원문을 글자·문장부호까지 그대로 옮기고 해당 문단 번호를 함께 쓴다. 요약이나 의역을 따옴표 안에 넣지 않는다.
- 문단 번호는 발췌문의 표기를 따른다. 번호가 없거나 불명확하면 임의로 붙이지 말고 사용자에게 확인을 요청한다.
- 원본 발췌문, 토론 규칙, 양식, 기존 검증기와 기존 산출물은 수정·삭제·이름 변경하지 않는다.
- 새 산출물은 작업 루트의 `결과물` 폴더에 저장한다. 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 새 파일명에 대해 승인받는다.

## 워크플로우

### 1. 발췌문 점검

- 문단 번호와 본문을 대응시켜 읽는다.
- 인용 가능한 원문과 쟁점을 내부적으로 정리하되, 발췌문 밖의 내용으로 빈틈을 채우지 않는다.
- 파일을 읽을 수 없거나 내용이 불완전하면 작업을 진행하지 말고 그 상태를 알린다.

### 2. 논제 후보

- 찬성과 반대가 모두 성립할 수 있는 명료한 논제 후보 3개를 기본으로 제안한다. 사용자가 개수를 정하면 그 수를 따른다.
- 각 논제에 관련 원문을 그대로 인용하고 문단 번호를 붙인다.
- 어느 한쪽 근거가 발췌문에서 충분히 나오지 않는 논제는 균형 잡힌 논제로 단정하지 말고 제한점을 표시한다.
- 사용자가 선택한 논제만 다음 단계에 사용한다.
- 기본 저장명: `결과물/논제후보.md`

### 3. 찬반 근거카드

- 선택 논제에 대해 찬성·반대 각 3장을 기본으로 작성한다. 사용자가 개수를 정하면 그 수를 따른다.
- 각 카드는 다음 순서를 지킨다.
  1. 주장 한 문장
  2. 원문 그대로의 인용과 문단 번호
  3. 주장과 근거의 연결 설명 2문장 이내
- 연결 설명도 발췌문이 보여 주는 범위를 넘지 않는다. 직접 확인할 수 없는 부분은 `발췌문에서 확인 불가`로 표시한다.
- 기본 저장명: `결과물/근거카드.md`

### 4. 활동지와 루브릭

- 승인된 논제와 근거카드를 바탕으로 대상 학년·수준에 맞게 작성한다.
- 활동지에는 최소한 논제, 입장 선택, 주장, 원문 인용, 문단 번호, 주장과 근거의 연결, 예상되는 상대 주장, 상대 근거, 반박 준비 칸을 둔다.
- 루브릭에는 최소한 근거 사용, 경청과 반박, 토론 태도를 포함하고 각 기준을 관찰 가능한 한 문장으로 쓴다.
- 점수 체계는 사용자가 제시한 것을 우선한다. 제시되지 않으면 간단한 초안을 만들되 배점은 검토가 필요함을 밝힌다.
- 기본 저장명: `결과물/활동지.md`, `결과물/루브릭.md`
- DOCX 등 추가 형식은 사용자가 요청하고 저장 목록을 승인한 경우에만 만든다.

### 5. 인용 검증

- 논제 후보, 근거카드, 활동지, 토론 로그 등 범위에 포함된 모든 직접 인용을 발췌문과 대조한다.
- 기존 검증기가 있으면 코드를 수정하지 않고 사용한다. 없으면 원문 검색으로 검증하며, 새 검증기 제작은 별도 요청과 승인이 있을 때만 수행한다.
- 판정은 다음처럼 구분한다.
  - `✔ 일치`: 인용문과 문단 번호가 원문과 정확히 일치
  - `△ 확인 필요`: 유사하지만 글자·문장부호·문단 번호에 차이가 있음
  - `✖ 발췌문에 없음`: 대응하는 원문을 찾을 수 없음
- `△`와 `✖`는 차이 또는 최근접 원문을 제시하되, 잘못된 인용을 임의로 원문처럼 고쳐 쓰지 않는다.
- 전체 인용 수와 판정별 건수를 요약하고 인용별 판정표를 만든다.
- 기본 저장명: `결과물/검증리포트.md`

## 완료 보고

- 변경하거나 생성한 내용, 파일 수, 최종 저장 절대 경로를 요약한다.
- 원본이 보존되었는지와 인용 검증 결과를 함께 알린다.
